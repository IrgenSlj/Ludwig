# Decisions

One line per decision: date, decision, reason. Newest at the bottom. Reversing a
decision is a new line, not an edit.

- 2026-11-11 — Ludwig becomes a pre-production check for fabricators; generation, the Studio, the desktop app and the MCP server are dropped. Reason: generation and reviewer-side drawing review are crowded; the fabricator side with structured data is not.
- 2026-11-11 — Continue in the existing repository; old code removed in one commit and kept at tag `harness-era-v1`. Reason: keep history and the project name.
- 2026-11-11 — First trade is joinery; first pack is `joinery-nl`. Reason: founder's daily domain.
- 2026-11-11 — Development uses public samples and invented fixtures only. Reason: no agreement yet to use any company's files.
- 2026-11-11 — First ERP adapter is a generic CSV/Excel importer with a mapping file. Reason: the target production software is not yet named.
- 2026-11-11 — All four input families are in scope (IFC, DXF/DWG, PDF, schedules), built in the order IFC and schedules, then DXF and PDF. Reason: all are common in practice; structured inputs give value soonest.
- 2026-11-11 — Verdicts are deterministic; LLM use is confined to `ludwig.assist`. Reason: published benchmarks show vision models unreliable on door and window symbols, and a work preparer must be able to trust a blocker.
- 2026-11-11 — Rules are data: IDS for required information, YAML with a small expression language for computed and cross-source checks. Reason: safe to accept packs from customers; reuse of an open standard.
- 2026-11-11 — Python 3.12, single package `ludwig` under `src/`. Reason: best IFC library; fixes the old top-level package name collisions.
- 2026-11-11 — No GPL or AGPL libraries in-process; pdfplumber instead of PyMuPDF; DWG via an external converter. Reason: the product will be sold closed-source.
- 2026-11-11 — CadQuery/OCCT geometry is not a dependency. Reason: first-trade checks are about attributes and dimensions, not solids. Revisit only if a rule needs it.
- 2026-11-11 — The files ARCHITECTURE section 6 keeps live in `reference/`, outside any package and excluded from lint, and each is deleted when the task that uses it lands. Reason: keeping them at their old paths would leave the old top-level packages (`agent`, `critic`, `toolkit`, `webapp`) in place.
- 2026-11-11 — Dev dependencies: pytest (MIT) and ruff (MIT). Reason: CI gate. Neither ships with the product.
- 2026-11-11 — Phase 1 starts before the phase 0 gate (error catalogue, 0.5/0.6) is met, on Irgen's instruction. Task 1.7 (first ten rules, chosen from the catalogue) waits for the catalogue; the engine tasks do not depend on it.
- 2026-11-11 — Dependency: IfcOpenShell 0.9.0.post1, LGPL-3.0-or-later (from the installed package metadata), used as an unmodified library. Dependency: PyYAML 6.0.3, MIT.
- 2026-11-11 — The IFC parser emits one architect element per (mark, width, height, mapped props), with quantity = occurrence count and one SourceRef per GlobalId. Occurrences without a mark stay one element each. Location is kept only when all occurrences share it. Reason: SPEC asks for quantity by mark, and matching is one-to-one by mark; a mark whose occurrences differ stays split so a consistency rule can report it.
- 2026-11-11 — Both IfcWindow and IfcDoor map to `frame` by default (the IFC occurrence is the whole unit as delivered); the mapping file can change this. Lengths are rounded to 0.1 mm at the parser boundary.
- 2026-11-11 — Default IFC mark is Revit's `Type Mark`, then `Pset_*Common.Reference`. Revit placeholder values (a parameter whose value is its own name) are read as not set and counted in a parse warning.
- 2026-11-11 — Dependency: openpyxl 3.1.5, MIT.
- 2026-11-11 — `Element.quantity` may be None when a schedule's quantity cell cannot be read (SPEC says int, default 1). Reason: hard rule 2; defaulting an unreadable quantity to 1 would let a count check pass silently.
- 2026-11-11 — Schedule mappings: `type` is a constant or a column with a value vocabulary (`other: skip|warn` for rows of other trades); `empty_values` lists cell values read as not set (default `""`, `"-"`). Each read cell is recorded in `field_sources`.
- 2026-11-11 — Expression language: `and`/`or` short-circuit left to right (so `is_set(x) and x > 3` is false, not not_checked, when x is unset); comparisons do not chain; a type mismatch or division by zero gives not_checked with the reason; `in` matches only values of the same kind. Reason: SPEC section 6 is silent on these, and each choice keeps a verdict from passing silently.
- 2026-11-11 — pack.yaml keys: `name`, `version` (text), `description`, `files` (`checks`, `limits`, `ids`; default file names), `match_tolerance_mm`. Rule keys: `id`, `kind`, `severity`, `applies_to` (`side`, `type`; each one value or a list), `when`, `message`, `description`, plus the kind's own keys. Expressions are compiled from the YAML text as written. Names are checked at load: element fields, `props.<standard prop>`, `limits.<existing path>`, `parent.<field>`; compare paths start with `architect.` or `erp.`. Reason: a typo in a pack must fail at load, not pass at run time.
- 2026-11-11 — Engine output: elements outside a rule's `applies_to` get no finding; a false `when` gives `not_applicable`; pass, fail and not_checked are all kept and reports choose what to list. `measured` is the element value the rule read (a dict when it read several); `expected` is the require text with limits filled in. A rule kind the engine does not run yet gives one not_checked finding. Reason: SPEC section 7 statuses and "never pass silently".
- 2026-11-11 — Rule fixtures are JSON element tables (`{"elements": [...]}`, id and sources optional); `ludwig.rules.fixtures.check` requires pass.* to give a pass and no fail, and fail.* to give a fail.
- 2026-11-11 — Reports: JSON holds every finding (fail, not_checked, pass, not_applicable) and no timestamps, so equal inputs give equal bytes. Excel puts fail and not_checked on `Findings` (sorted by severity, then status), passes on `Passed`, counts on `Summary`, and parse warnings on their own sheet; not_applicable is counted, not listed. Every text cell is written as a string so customer data cannot become a formula.
- 2026-11-11 — CLI: an architect schedule (.xlsx/.csv) is read with the mapping file `<name>.mapping.yaml` beside it. A missing input file, an unsupported extension, a bad pack or a missing mapping is a usage error (exit 2); an unreadable file is a parse warning. `--erp`/`--mapping` give a usage error until phase 2. Reason: CLAUDE.md shows no flag for architect mappings; a typo in a path must not produce a clean report.
- 2026-11-11 — `consistent` rules: architect elements in scope are grouped by `group_by`; a document is an element's first source file. `quantity` is compared as a total per document, and a document with elements in the rule's scope but none in the group counts 0 (so "in the model, not on the schedule" fails); with one document the count check is not_applicable. Other fields must take one value per group across and within documents, within an optional `tolerance`. A missing group key or value gives not_checked.
- 2026-11-12 — Phase 2 starts before the Phase 1 gate, on Irgen's instruction to continue all planned development. 2.1 stays open: the ERP export is invented (`fixtures/erp/`) and its column names come from no real system; rework the mapping when the real export arrives.
- 2026-11-12 — The ERP adapter reuses the schedule mapping format (columns, units, type vocabulary with `other: skip`). `--mapping` defaults to `<name>.mapping.yaml` beside the export, like architect schedules; `--mapping` without `--erp` is a usage error.
- 2026-11-12 — Matching works on positions, not single rows: all architect elements of one type and mark (model group plus schedule rows) pair with all ERP elements of that type and mark. Fallback applies only when a position lacks a mark on at least one side; it needs the same type, the same location when both state one (ignoring case and spaces), and width and height within `match_tolerance_mm`. Fallback candidates form connected groups; a group of exactly one architect and one ERP position matches, anything larger is `ambiguous`. The `Match` record lives in `model.py` so the engine can take pairs without importing the matcher.
- 2026-11-12 — `compare` rules run once per matched position (unmatched and ambiguous positions get their findings from matching, PLAN 2.5). Each side's value is kept per document: `quantity` as the document total, other fields as the distinct values. Every left value must agree with every right value: numbers within `tolerance`, text equal ignoring case and surrounding spaces, mixed kinds not_checked. The architect side uses the values its documents state, since gaps between architect documents belong to `consistent` rules; every ERP element must state the value, else not_checked. A `when` filter applies if it is true for any element of the position. Without production data each compare rule gives one not_checked finding. `measured` is `{left path: {document: value}, right path: {...}}`; message placeholders `{architect.<field>}` and `{erp.<field>}` show those values per document.
- 2026-11-12 — Text properties can carry a `values` vocabulary in IFC and schedule mappings (keys ignore case; values not listed are kept as read). Opening direction uses `left`/`right`: IFC `SINGLE_SWING_LEFT/RIGHT` and Dutch `links/rechts` map to it, so model, schedule and export compare like with like.
- 2026-11-12 — New rule kind `unmatched` (`missing_on: erp|architect`, `applies_to: {type}` only): one finding per position, pass when paired, fail when missing on that side, not_checked when ambiguous. SPEC section 5 asks for findings on unmatched elements; a rule kind keeps their severity, message and fixtures in the pack like every other rule. SPEC section 6 updated.
- 2026-11-12 — `compare` on fields other than quantity: each side's distinct values must each have a counterpart on the other side (numbers within tolerance, text ignoring case). When a position has several text values (mark 28: two left, two right), every document that states the value for all its elements must also hold them in the same quantities. A `when` filter applies if true for any element of the position, is not_applicable if false for any and true for none, else not_checked.
- 2026-11-12 — A schedule or export prop may set `default` for an empty cell (`fire_rating_min: default 0`): an export that leaves the fire column blank for ordinary doors states "no rating", and the fire-rating compare must fail on 30 vs blank rather than say not_checked.
- 2026-11-12 — packs/joinery-nl starts with the eight reconciliation rules of PLAN 2.5. The 1 mm width/height tolerance and 2 mm match tolerance are placeholders until a factory states its own.
- 2026-11-12 — The Excel report replaces the Measured and Source columns with Drawings / Production values and Drawings source / Production source. Compare and unmatched findings fill both sides from `measured`; any other finding's value goes to the side its evidence comes from (ERP evidence: production). One document shows the bare value; several show `file: value` each. JSON keeps `measured` as is.
- 2026-11-12 — Phase 3 starts on the same instruction as phase 2 (continue all planned development); the phase 1 gate is still open for 1.7.
- 2026-11-12 — Dependency: ezdxf 1.4.5, MIT. Reads DXF in-process; damaged files go through `ezdxf.recover` and repairs become a parse warning.
- 2026-11-12 — DXF parser: model-space INSERTs whose block name matches a mapped pattern (fnmatch, ignoring case) on a mapped layer (empty list: all layers) become elements, grouped like IFC occurrences (type, mark, width, height, props); one source per INSERT with handle and layer. Sizes come from attributes first (mapping `units`), then block extents along the block's own x or y axis times the insert scale, in `$INSUNITS` (0 or unknown: millimetres, with a warning). The default mapping takes only width from extents, because in a floor plan y is the wall depth. `.dxf` files use `<name>.mapping.yaml` beside them when present, else the default mapping.
- 2026-11-12 — Invented 2D fixtures are generated by `tools/make_duplex_2d.py` from the Duplex model, so the 2D delivery describes the same project as the IFC version; ezdxf's fixed-metadata option keeps the bytes stable.
- 2026-11-12 — Drawn tables: a DXF mapping may list `tables`, each a schedule mapping plus the `layers` holding its lines and text. Horizontal and vertical segments (LINE, polylines) give the row and column rules; each TEXT/MTEXT lands in the cell holding the centre of its extents; the rows then go through the same code as spreadsheets (`schedule.parse_rows`). Evidence is the drawn cell (A1 style), the handle of its first text and the layer. The grid code (`parsers/tables.py`) is shared with PDF tables.
- 2026-11-12 — Dependency: pdfplumber 0.11.10, MIT; it brings pdfminer.six (MIT), pypdfium2 (BSD-3-Clause/Apache-2.0, PDFium's bundled libraries under permissive licences) and Pillow (MIT-CMU). No GPL or AGPL. PyMuPDF stays excluded.
- 2026-11-12 — PDF schedules: a `.pdf` needs `<name>.mapping.yaml` beside it, a schedule mapping plus optional `pages`. Each page's ruled table comes from pdfplumber's edges and words through the shared grid; continuation pages drop rows equal to the header. A page without words is a parse warning ("no vector text, not read"), as is a page without rules. Evidence is the page number and the box of the cell's words in PDF points from the page's top-left corner, plus an A1-style cell counted over the joined table.
- 2026-11-12 — Invented PDFs are written by `tools/minipdf.py` (lines and Helvetica text, fixed bytes), so no PDF writer becomes a dependency.
- 2026-11-12 — DWG: Ludwig does not convert. A person or script converts DWG to DXF with a separate program (ODA File Converter, or a CAD package), documented in `docs/DWG.md`; `.dwg` on the command line is a usage error pointing there. Shipping or hosting a converter needs its licence checked first.
- 2026-11-12 — Office conventions: every input reads `<name>.mapping.yaml` beside it; for IFC and DXF it is optional (built-in default otherwise), for schedules and exports required. Example office mappings live in `mappings/examples/` as starting points; the AIA layer names there (`A-DOOR`, `A-GLAZ`) follow the US National CAD Standard. No Dutch layer standard (NLCS) mapping yet: its layer names must be checked against the current NLCS text first.
- 2026-11-12 — Phase 4 order: 4.4, 4.2 and 4.3 before 4.1. IDS needs the element table to keep data it does not hold today (IFC class, raw property sets, classification, material), a data model change worth doing last in the phase.
- 2026-11-12 — Pack hash: sha256 over the path and bytes of pack.yaml, checks, limits and the IDS file, sorted by path; fixtures do not count. Reports carry it as `pack.hash` (`sha256:<hex>`) in JSON and "Pack hash" on the Excel summary. Packs are checked out without line-ending conversion so the hash is the same on every OS.
- 2026-11-12 — BCF: version 2.1 (the version most model checkers read), written with the standard library (zipfile, ElementTree), no package. One topic per failed blocker or warning; topic and viewpoint ids are uuid5 of pack, rule and element ids, so a re-run gives the same ids. The viewpoint selects and colours (blocker red, warning orange) the IFC GlobalIds in the evidence, with no camera; findings without model elements get a viewpoint without selection. The output was validated against the official buildingSMART BCF-XML 2.1 schemas (markup.xsd, visinfo.xsd, version.xsd) on 2026-11-12; the schemas are not vendored. The CLI writes `report.bcf` beside the JSON and Excel reports.
- 2026-11-12 — Evidence of a grouped IFC element lists every occurrence's GlobalId for any field without its own source (`Element.sources_of`), so a BCF topic selects all doors of a position, not the first.
- 2026-11-12 — Dependency: pypdf 7.0.1, BSD-3-Clause, no required dependencies. PDF markup writes `<name>.marked.pdf` into the report folder for each source PDF that is evidence of a fail or not_checked finding: a Square annotation 2 pt around the cell's words (red blocker, orange warning, blue info, grey not_checked) with the message (and reason) as its contents and `ludwig <rule>` as author. The source PDF is never written.
- 2026-11-12 — IDS: own reader and evaluator (`rules/ids.py`, standard library XML), not IfcOpenShell's ifctester: ifctester checks an IFC file, while ARCHITECTURE has IDS run on the element table. The IFC parser keeps per-occurrence facts on each element (`Element.facts`, aligned with `sources`): IFC entity, predefined type, scalar attributes, property sets (inherited from the type, Revit name placeholders dropped), classification references and material names, plus the project length unit. SPEC section 3 updated.
- 2026-11-12 — IDS semantics: an occurrence is in scope when every applicability facet is satisfied; required facets must be satisfied, prohibited ones must not, optional ones only when present. Values: simple values (numbers within 1e-6 relative, booleans as true/false), enumeration, pattern (Python regex; one it cannot compile is not_checked), min/max inclusive/exclusive, length/minLength/maxLength. Length, area and volume measures are converted to SI before comparison. partOf and any other restriction give not_checked. One finding per element with applicable occurrences (evidence: the failing occurrences); a specification with minOccurs/maxOccurs also gets one finding on the count; with no IFC model in the input each specification is one not_checked finding. Rule ids are `ids-<specification name>`; severity comes from pack.yaml `ids_severity` (default warning), since IDS has none.
- 2026-11-12 — Phase 5 starts on the same standing instruction; the phase 4 gate (BCF opened in two viewers) waits for a person.
- 2026-11-12 — Service dependencies, in the optional `api` extra so the command line stays small: FastAPI 0.162 (MIT), Starlette (BSD-3-Clause), Pydantic (MIT), uvicorn (BSD-3-Clause), SQLAlchemy 2.1 (MIT), psycopg 3.3 with psycopg-binary (LGPL-3.0, used as an unmodified library like IfcOpenShell; bundles libpq under the PostgreSQL licence), python-multipart (Apache-2.0). Dev: httpx (BSD-3-Clause) for the test client. certifi (MPL-2.0) comes with httpx, unmodified.
- 2026-11-12 — Service shape (5.1): `ludwig.check` runs a check for both the CLI and the service. Tables project, upload, run, finding (company, user and review arrive with 5.2/5.3). Uploads are stored once per sha256; a run records pack name, version and hash plus its upload ids and hashes, so it can be repeated. A mapping is an upload with role `mapping` that names the file it describes; the job lays each file out in its own folder with its mapping beside it, then calls the same code as the CLI. Runs execute as a FastAPI background task after the response (one process; a queue is not needed at pilot volume). Tables are created on start; migrations come with the first schema change. Packs are the folders under LUDWIG_PACKS_DIR. Guards: optional bearer token (LUDWIG_API_TOKEN) and a same-origin rule for browser writes, ported from the old daemon (reference/http_guards.py removed). Tests run on SQLite and, in CI, on Postgres 16.
- 2026-11-12 — Service routes live under `/api`; `/` serves the web build when LUDWIG_WEB_DIR points to one. Findings, reports and parse warnings name files by their upload name (with the upload id when two uploads share a name), never the job's temporary paths; the run carries `files` (name -> upload id). PDF markup is written before that relabelling, from the laid-out copies.
- 2026-11-12 — Reviews: accept or dismiss, a dismissal needs a reason; rows are never edited, the latest counts. The CSV export lists fail and not_checked findings with the latest decision; text starting with = + - @ gets a leading apostrophe so a spreadsheet does not run it. PDF pages are rendered for the finding view at 1.5 px per point through pdfplumber (pypdfium2), no new dependency.
- 2026-11-12 — Web app (5.2) in `web/`: Vite 5, React 18, TypeScript 5, tested with Vitest; versions pinned exactly. Runtime bundle is React and ReactDOM only (MIT); build tools are MIT/ISC/Apache-2.0/BSD, plus caniuse-lite data (CC-BY-4.0) used at build time only. Hash routing so `/api` stays the service's. Screens: projects; project (uploads with their mappings, pack choice, runs); run (counts, open/not reviewed/all filter, drawings and production side by side, exports Excel/CSV with reviews/BCF/JSON/marked PDFs); finding (both sides with sources, PDF page with the evidence box, accept/dismiss with reason, history, next open finding). Files and page images go through fetch so a token is sent. Checked by hand against a running service on 2026-11-12.
- 2026-11-12 — Compare evidence lists only elements that state the compared value; a plan with no glazing data is not cited as a source of glazing.
- 2026-11-12 — No company accounts for now (Irgen): keep the service single-tenant with the optional shared token, and put effort into the checking software. PLAN 5.3 deferred; the hosted cloud part of 5.4 waits with it.
