# Decisions

One line per decision: date, decision, reason. Newest at the bottom. Reversing a
decision is a new line, not an edit.

- 2026-11-11 — Ludwig becomes a pre-production check for fabricators; generation, the Studio, the desktop app and the MCP server are dropped. Reason: generation and reviewer-side drawing review are crowded; the fabricator side with structured data is not.
- 2026-11-11 — Continue in the existing repository; old code removed in one commit and kept at tag `harness-era-v1`. Reason: keep history and the project name.
- 2026-11-11 — First trade is joinery; first pack is `joinery-nl`. Reason: founder's daily domain.
- 2026-11-11 — Development uses public samples and invented fixtures only. Reason: no agreement yet to use any company's files.
- 2026-11-11 — First ERP adapter is a generic CSV/Excel importer with a mapping file. Reason: the target production software is not yet named.
- 2026-11-11 — All four input families are in scope (IFC, DXF/DWG, PDF, schedules), built in the order IFC and schedules, then DXF and PDF. Reason: all are common in practice; structured inputs give value soonest.
- 2026-11-11 — Verdicts are deterministic; LLM use is confined to `ludwig.assist`. Reason: published benchmarks show vision models unreliable on door and window symbols, and a work preparer must be able to trust a blocker.
- 2026-11-11 — Rules are data: IDS for required information, YAML with a small expression language for computed and cross-source checks. Reason: safe to accept packs from customers; reuse of an open standard.
- 2026-11-11 — Python 3.12, single package `ludwig` under `src/`. Reason: best IFC library; fixes the old top-level package name collisions.
- 2026-11-11 — No GPL or AGPL libraries in-process; pdfplumber instead of PyMuPDF; DWG via an external converter. Reason: the product will be sold closed-source.
- 2026-11-11 — CadQuery/OCCT geometry is not a dependency. Reason: first-trade checks are about attributes and dimensions, not solids. Revisit only if a rule needs it.
- 2026-11-11 — The files ARCHITECTURE section 6 keeps live in `reference/`, outside any package and excluded from lint, and each is deleted when the task that uses it lands. Reason: keeping them at their old paths would leave the old top-level packages (`agent`, `critic`, `toolkit`, `webapp`) in place.
- 2026-11-11 — Dev dependencies: pytest (MIT) and ruff (MIT). Reason: CI gate. Neither ships with the product.
- 2026-11-11 — Phase 1 starts before the phase 0 gate (error catalogue, 0.5/0.6) is met, on Irgen's instruction. Task 1.7 (first ten rules, chosen from the catalogue) waits for the catalogue; the engine tasks do not depend on it.
- 2026-11-11 — Dependency: IfcOpenShell 0.9.0.post1, LGPL-3.0-or-later (from the installed package metadata), used as an unmodified library. Dependency: PyYAML 6.0.3, MIT.
- 2026-11-11 — The IFC parser emits one architect element per (mark, width, height, mapped props), with quantity = occurrence count and one SourceRef per GlobalId. Occurrences without a mark stay one element each. Location is kept only when all occurrences share it. Reason: SPEC asks for quantity by mark, and matching is one-to-one by mark; a mark whose occurrences differ stays split so a consistency rule can report it.
- 2026-11-11 — Both IfcWindow and IfcDoor map to `frame` by default (the IFC occurrence is the whole unit as delivered); the mapping file can change this. Lengths are rounded to 0.1 mm at the parser boundary.
- 2026-11-11 — Default IFC mark is Revit's `Type Mark`, then `Pset_*Common.Reference`. Revit placeholder values (a parameter whose value is its own name) are read as not set and counted in a parse warning.
- 2026-11-11 — Dependency: openpyxl 3.1.5, MIT.
- 2026-11-11 — `Element.quantity` may be None when a schedule's quantity cell cannot be read (SPEC says int, default 1). Reason: hard rule 2; defaulting an unreadable quantity to 1 would let a count check pass silently.
- 2026-11-11 — Schedule mappings: `type` is a constant or a column with a value vocabulary (`other: skip|warn` for rows of other trades); `empty_values` lists cell values read as not set (default `""`, `"-"`). Each read cell is recorded in `field_sources`.
- 2026-11-11 — Expression language: `and`/`or` short-circuit left to right (so `is_set(x) and x > 3` is false, not not_checked, when x is unset); comparisons do not chain; a type mismatch or division by zero gives not_checked with the reason; `in` matches only values of the same kind. Reason: SPEC section 6 is silent on these, and each choice keeps a verdict from passing silently.
- 2026-11-11 — pack.yaml keys: `name`, `version` (text), `description`, `files` (`checks`, `limits`, `ids`; default file names), `match_tolerance_mm`. Rule keys: `id`, `kind`, `severity`, `applies_to` (`side`, `type`; each one value or a list), `when`, `message`, `description`, plus the kind's own keys. Expressions are compiled from the YAML text as written. Names are checked at load: element fields, `props.<standard prop>`, `limits.<existing path>`, `parent.<field>`; compare paths start with `architect.` or `erp.`. Reason: a typo in a pack must fail at load, not pass at run time.
- 2026-11-11 — Engine output: elements outside a rule's `applies_to` get no finding; a false `when` gives `not_applicable`; pass, fail and not_checked are all kept and reports choose what to list. `measured` is the element value the rule read (a dict when it read several); `expected` is the require text with limits filled in. A rule kind the engine does not run yet gives one not_checked finding. Reason: SPEC section 7 statuses and "never pass silently".
- 2026-11-11 — Rule fixtures are JSON element tables (`{"elements": [...]}`, id and sources optional); `ludwig.rules.fixtures.check` requires pass.* to give a pass and no fail, and fail.* to give a fail.
- 2026-11-11 — Reports: JSON holds every finding (fail, not_checked, pass, not_applicable) and no timestamps, so equal inputs give equal bytes. Excel puts fail and not_checked on `Findings` (sorted by severity, then status), passes on `Passed`, counts on `Summary`, and parse warnings on their own sheet; not_applicable is counted, not listed. Every text cell is written as a string so customer data cannot become a formula.
- 2026-11-11 — CLI: an architect schedule (.xlsx/.csv) is read with the mapping file `<name>.mapping.yaml` beside it. A missing input file, an unsupported extension, a bad pack or a missing mapping is a usage error (exit 2); an unreadable file is a parse warning. `--erp`/`--mapping` give a usage error until phase 2. Reason: CLAUDE.md shows no flag for architect mappings; a typo in a path must not produce a clean report.
